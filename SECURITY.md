# Open ERC Composition Laboratory (OECL)

# Security Policy

Version 1.0

---

# Purpose

This document describes the security policy of the Open ERC Composition Laboratory (OECL).

The objective of this policy is to encourage responsible disclosure of security-related issues while preserving the integrity, reproducibility, and long-term sustainability of the project.

---

# Project Scope

The Open ERC Composition Laboratory (OECL) is an independent open research project dedicated to deterministic Ethereum protocol composition.

OECL is currently maintained by **tenio.eth**.

The project primarily consists of research infrastructure, deterministic experimentation tools, analytical engines, and supporting documentation.

OECL is not intended to operate production blockchain infrastructure or custodial services.

---

# Supported Versions

Security reports are accepted for the latest development version of the project.

Older experimental versions may not receive security updates.

---

# Reporting Security Issues

If you discover a potential security issue affecting OECL, please report it responsibly.

Security reports should include, whenever possible:

* a clear description of the issue;
* affected components;
* reproduction steps;
* expected behavior;
* observed behavior;
* potential impact;
* suggested remediation (if available).

Responsible disclosure is encouraged.

Public disclosure before the issue has been evaluated is discouraged whenever practical.

---

# Scope of Security Reports

Examples of relevant reports include:

* vulnerabilities affecting deterministic execution;
* integrity issues within research datasets;
* incorrect validation logic;
* reproducibility failures caused by implementation defects;
* security vulnerabilities affecting project tooling;
* supply-chain vulnerabilities within project dependencies.

General feature requests are outside the scope of this policy.

---

# Research Integrity

For OECL, scientific integrity is considered part of project security.

Issues affecting:

* reproducibility;
* deterministic validation;
* experimental correctness;
* benchmark integrity;
* research data integrity;

may be treated with the same priority as traditional software defects.

---

# Dependency Management

Project dependencies should remain:

* actively maintained;
* publicly available;
* appropriately licensed;
* regularly reviewed.

Security updates should be applied whenever appropriate while preserving deterministic behavior.

---

# Coordinated Disclosure

When practical, confirmed vulnerabilities should be addressed before public disclosure.

Contributors are encouraged to coordinate disclosure with the project maintainers to minimize unnecessary risk.

---

# Security Limitations

OECL is a research platform.

The project does not guarantee suitability for:

* production deployments;
* financial systems;
* safety-critical infrastructure;
* security-critical environments.

Users remain responsible for evaluating whether OECL is appropriate for their intended use.

---

# Contact

Security-related questions and responsible disclosure should be directed to the project maintainers.

Future dedicated security contact information may be published as the project evolves.

---

# Guiding Principle

Security within OECL extends beyond software vulnerabilities.

Protecting reproducibility, deterministic execution, experimental integrity, and scientific credibility is considered essential to maintaining the long-term value of the Open ERC Composition Laboratory.
