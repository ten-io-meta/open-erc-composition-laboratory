# Open ERC Composition Laboratory (OECL)

# Contributing

Version 1.0

---

# Introduction

Thank you for your interest in contributing to the Open ERC Composition Laboratory (OECL).

OECL is an independent open research project dedicated to deterministic Ethereum protocol composition.

The project provides an open scientific infrastructure for reproducible experimentation, protocol interoperability research, and long-term knowledge accumulation across the Ethereum ecosystem.

OECL is currently maintained by **tenio.eth**.

Contributions are welcome from researchers, protocol authors, developers, auditors, and members of the Ethereum community who share the project's commitment to rigorous, reproducible scientific research.

---

# Purpose

The objective of contributing to OECL is not simply to add new functionality.

Every accepted contribution should improve the project's ability to generate reproducible scientific knowledge about Ethereum protocol composition.

Contributions are expected to strengthen the quality, reproducibility, maintainability, or long-term sustainability of the research platform.

---

# Guiding Principles

Every contribution should improve one or more of the following:

* reproducibility;
* deterministic validation;
* protocol interoperability;
* experimental quality;
* research methodology;
* documentation quality;
* architectural consistency;
* long-term maintainability.

Contributions should preserve the modular architecture and scientific objectives of OECL.

---

# Types of Contributions

Examples of accepted contributions include:

* protocol adapters;
* experiment scenarios;
* benchmark improvements;
* validation rules;
* protocol manifests;
* analytical engines;
* dataset improvements;
* research tooling;
* documentation improvements;
* bug fixes;
* performance improvements.

All contributions should be directly related to the objectives of the project.

---

# Pull Requests

Before submitting a Pull Request, contributors should ensure that:

* the project builds successfully;
* deterministic behavior is preserved;
* existing experiments remain reproducible;
* new functionality includes appropriate documentation;
* unrelated changes are not combined in the same Pull Request;
* architectural consistency is maintained.

Small, focused Pull Requests are preferred over large unrelated modifications.

---

# Coding Standards

Contributors should:

* write clear and maintainable code;
* preserve modularity;
* follow the existing architectural structure;
* keep responsibilities clearly separated;
* avoid unnecessary complexity;
* preserve deterministic behavior whenever applicable.

Code quality is considered part of the scientific quality of the project.

---

# Research Standards

Experimental contributions should be reproducible whenever possible.

Research conclusions should be supported by observable experimental evidence rather than assumptions.

Where appropriate, contributors are encouraged to provide datasets, reports, benchmarks, or documentation supporting their work.

---

# Documentation Standards

New capabilities should include documentation describing:

* purpose;
* architecture;
* expected inputs;
* expected outputs;
* research motivation;
* limitations where applicable.

Documentation is considered an integral part of every accepted contribution.

---

# Intellectual Property

The Open ERC Composition Laboratory (OECL) is currently maintained by **tenio.eth**.

Contributors retain the copyright to their original work.

Submitting a contribution does not transfer copyright ownership.

Accepted contributions may become subject to the Contributor License Agreement (CLA) adopted by the project.

The purpose of the CLA is to grant the project the rights necessary to maintain, improve, distribute, evolve, and, where applicable, commercially use accepted contributions as part of the OECL ecosystem while preserving contributor ownership.

The complete intellectual property policy is documented in:

* `docs/IP_POLICY.md`

The Contributor License Agreement is documented in:

* `docs/CLA.md`

---

# Review Process

Every contribution is reviewed according to:

* technical correctness;
* reproducibility;
* architectural consistency;
* documentation quality;
* scientific value;
* long-term maintainability.

Acceptance is based on technical merit and scientific quality rather than contributor identity.

---

# Community

OECL encourages:

* respectful technical discussion;
* constructive scientific debate;
* protocol experimentation;
* evidence-based research;
* collaborative problem solving.

The objective is to improve scientific understanding of Ethereum protocol composition through open collaboration.

All contributors are expected to follow the project's Code of Conduct.
