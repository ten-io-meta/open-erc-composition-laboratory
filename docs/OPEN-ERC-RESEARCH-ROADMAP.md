# OECL Open ERC Research — corpus, evidence and publication boundary

Status: DRAFT · Branch: `feature/erc-research-github-magicians-web-v1`

## Original scientific mission

OECL evaluates *interactions between ERCs*, asks which new behavior appears **only in a composition**, and determines whether the behavior is viable **within explicit participant boundaries**. It is not a standards-ranking service and does not promote any one ERC.

## Source hierarchy (do not conflate)

1. **Merged official ERC source** — current `ethereum/ERCs` files, pinned Git SHA. Documentary requirements/semantics, not executable compatibility.
2. **Open proposal pull request** — source files changed in `ethereum/ERCs` PRs with exact matching `ERCS/erc-N.md`; immutable PR blob SHA; editorial status is **unmerged**, not canonical. PR issues with no matching file are not accepted as specifications.
3. **Ethereum Magicians** — public forum search / linked discussion, with source availability, thread URL, and author context. Comments and preferences are claims, **not protocol guarantees**.
4. **Implementation and runtime evidence** — independently pinned repositories and executable tests, with compiler settings, target contracts, observations and exact block/run identities where applicable.
5. **Scientific composition assessment** — candidate boundaries, participant contribution/need matching, globally supported configuration, Harmony, ablation experiments, adversarial counterexamples and reproducible receipt.

These tiers never upgrade themselves. `requires` indicates a documented specification dependency, and an explicit textual mention is weaker. Neither is evidence of successful interoperability.

## What this PR actually provides

- All currently merged official ERC documents (626 in pinned snapshot) parsed into one read-only corpus, each with document identity, editorial status, title, abstract excerpt, requires, cross-references, discussion link and immutable Git origin. The source revision, count and non-certification state are tested.
- A generic read-only lookup for open ERC proposals, with GitHub PR changed-file matching and source identity checks, so unmerged proposals such as ERC-8060 are not misleadingly labeled absent or final.
- Bounded public Ethereum Magicians topic search with source-unavailable state and links to discussion URLs declared in ERC specifications.
- Pair research API and UI, which expose documentary relations, existing frozen scientific projections when available, missing experiment requirements, and **zero newly verified emergent properties** from documentary analysis alone.
- Scheduled **read-only** source-index refresh produces an artifact for human review; it does not auto-update production or merge code.

## Definition of a scientifically defensible emergent property (next integration)

A finding must declare:

- **Property**: falsifiable state/transition predicate not guaranteed by the participant protocols in isolation.
- **Participants**: ERC identities and exact verified implementation revisions.
- **Composition configuration**: contracts and adapters, shared execution environment, functions and required order, constraints, configured authority.
- **Observed new behavior**: deterministic witness, raw traces and derived invariant evaluation.
- **Counterfactual**: equivalent standalone and participant-removal/ablation runs showing that the same behavior is absent or meaningfully different without the composition.
- **Adversarial boundaries**: reentrancy, accounting exhaustion, double commitment, undercollateralization, operator privilege, transfer/burn races, liveness, integration-specific assumptions, as applicable.
- **Independent evidence**: receipts, executable test commands, seed, runtime, source provenance and exact run hash.
- **Scope**: known valid configurations, unsupported subsets, observed violations, unresolved evidence.

Verdicts:
- `DOCUMENTARY_ONLY`: a source relationship is visible; **not compatible by default**.
- `INCONCLUSIVE`: incomplete implementation or runtime evidence.
- `SUPPORTED`: the *exact tested configuration and property* are supported by runs, not universally certified.
- `CHALLENGED`: exact observed violation with evidence; another configuration may remain open.
- `PARTIAL`: only a strict subset is supported.
- `EMERGENT_PROPERTY_SUPPORTED`: a property meets the full composition/ablation/boundary evidence contract; not currently generated by this PR.

No LLM or synthetic score may create a firm verdict by writing plausible prose.

## Next engineering stages (reviewed PRs)

1. **Research feed**: versioned incremental source refresh for official ERCs, open proposal PRs, and paginated Ethereum Magicians discussions with rate limiting, source independence and chronology.
2. **Candidate scheduling**: compute potential pairs/groups from explicit dependencies, contribution/need and interaction evidence, rather than treating every pair of ERC numbers as known-compatible.
3. **Execution gateway**: pipe candidates into the existing OECL composition solver/Harmony/constraint engines; distinguish documented relations from independently executable composition targets.
4. **Emergence study**: baseline and ablation experiments plus global boundary observation. Only this stage may label genuinely new properties.
5. **Public scientific reports**: machine-readable findings and web drill-down, positive/negative/inconclusive outcomes, raw receipts, and repeatable experiment links.

Do not run hundreds of forum searches concurrently or imply that inspecting every document equals verifying every possible ERC combination. Do not change production frontend, historical contracts or onchain rights in this PR.
